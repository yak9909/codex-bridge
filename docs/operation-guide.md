# codex-bridge 運用手順書（依頼主＝あなた向け）

貸す人の PC の Codex に、あなたの PC のフォルダで作業してもらうための手順です。
貸す人向けの手順は [friend-guide.md](friend-guide.md) です。配布する zip は 1 つで、依頼主も貸す人も同じものを使います。

v0.3.0 では、複数の貸す人に別々の作業を頼めます。共有するフォルダも、この PC 内の複数の場所を登録できます。

---

## A. 最初に一度だけ

事前に、この PC に Tailscale を入れてログインしておいてください（[C. Tailscale の準備](#c-tailscale-の準備)）。

### A-1. 「使う」タブから準備する

`codex-bridge.exe` をダブルクリックすると、タスクトレイに常駐します。CB アイコンを左クリックするか、右クリック →「画面を開く」で http://127.0.0.1:8766/ を開きます。「使う」「貸す」「ログ」のタブがあります。

初回は「使う」タブの「準備を始める」を押します。Tailscale とファイアウォールを設定するコンソールが開くので、質問に答えます（Enter だけで、おすすめの設定になります）。終わると「使う」が自動で動き始めます。
共有フォルダは初期設定では聞きません。「使う」→「共有フォルダ」の「フォルダを追加」で選んでください。再起動なしで使えるようになり、次の起動でも設定が残ります。初期設定をやり直しても、選んだ共有フォルダと権限はそのままです。

| 段階 | 起きること | あなたがすること |
|---|---|---|
| 1. Tailscale の確認 | この PC の Tailscale の IP を調べる | 未接続なら案内に従ってログイン |
| 2. 検索用の部品 | ripgrep を用意 | なし |
| 3. 設定ファイルと権限の規則 | `host.yaml` と `data/policy.yaml` を作る | 必要なら、あとで画面から権限を変える |
| 4. ファイアウォール | Windows が「変更を許可しますか？」と聞く | 「はい」を押す |
| 5. 完了 | Tailscale の画面を開くか聞く | この PC の「…」→「Share...」から招待リンクを貸す人に送る |

初期設定だけを行う場合は `setup.bat`、または `codex-bridge.exe host setup` も使えます。

### A-2. `install-mcp.bat`

Claude Code と Codex（入っているほう）に codex-bridge を登録します。これで、エージェントに頼むだけで使えるようになります。
Claude Code / Codex の接続先は引き続き `http://127.0.0.1:8770` です。`install-mcp.bat` の使い方は変わりません。`codex-bridge.exe host install-mcp` も使えます。後から Claude Code や Codex を入れたときは、もう一度実行してください。

### アップデート

v0.3.1 以降の exe 版では、「ログ」タブで現在の版と更新状態を確認できます。起動時と 6 時間ごとに GitHub の公開リリースを調べます。「確かめる」でも確認できます。既定の「毎回確認する」では、新しい版が見つかったら「更新する」を押します。「自動で更新する」にすると、見つけ次第準備を始めます。どちらの設定でも、取得した ZIP は SHA-256 で照合します。

更新の準備が整うと、新しい依頼は「アップデート待ち」になります。この PC の使う側と貸す側の作業が終わると再起動し、待っていた依頼を送ります。10 分以内に再開できなければ、その依頼は失敗として知らせが届きます。指定した貸す人が更新中の場合は、その人が戻るまで最長 10 分待ちます。待っている依頼は「中止」で取り消せます。「更新をやめる」を押すと、この PC の切り替え待ちが解除され、預かっていた依頼を送ります。次に「確かめる」を押すまでは、同じ版の更新を再開しません。

v0.3.0 から v0.3.1 への移行は、次の手順で手動で行います。

新しい zip は、以前とは別のフォルダに展開されます。以前の設定をコピーせずに「準備を始める」を押すと、新しい設定になります（新しい招待コードが必要になり、権限の規則と共有フォルダも引き継がれません）。次の順で行ってください。

1. 古いアプリをトレイの「終了」で止める。コンソールで起動している場合は古いフォルダの `stop.bat` を使う
2. 新しい zip を展開する
3. 古いフォルダの `host.yaml` と `data` フォルダを、新しいフォルダにコピーする
4. 新しいフォルダの exe をダブルクリックするか、コンソールで使う場合は `start.bat` を実行する
5. 新しいフォルダの `install-mcp.bat` を実行し直す

v0.2 からの更新でも、`install-mcp.bat` で Codex を登録し直し、知らせ用フックを入れる必要があります。Codex では `/hooks` でフックを信頼してください。フックが変わったときは、もう一度信頼します。

以前の版で作られた `friend-kit` フォルダは不要なので、消してかまいません。

### 貸す人に渡すもの

1. 同じ zip（`codex-bridge-v` で始まる名前）。貸す人は展開して exe をダブルクリックし、画面の「貸す」タブにコードを貼って「つなぐ」を押します。
2. Tailscale の共有の招待リンク（A-1 の「Share...」で作ったもの）。
3. 招待コード: 「使う」→「招待」→ 貸す人を見分ける名前を入力 →「招待コードを発行」→ その場でコピー。

**招待コードは、貸す人ごとに別の名前で 1 つずつ発行します。** この名前が依頼の送り先になります。同じコードを複数の人に渡さないでください。発行し直すと、前のコードは使えなくなります。新しい招待のコマンド実行は「毎回承認」です。

以前の v0.1 の exe も、v0.3.0 の依頼主側につなげられます。この版の貸す人側の画面や設定を使うには、exe も v0.3.0 に更新してください。更新するときは依頼主側を先に更新します。v0.2 の exe でも通常の依頼は受けられますが、モデルと推論の強さは指定できません。
メイン以外のフォルダを使うには、貸す人側の exe も v0.2 以降が必要です（v0.1 の exe はメインのフォルダだけで作業できます）。

※ OpenAI の規約上グレーな使い方なので、貸す人に伝えて了解をもらってください。

## B. 毎回

### 起動と停止

`codex-bridge.exe` をダブルクリックします。設定済みなら「使う」は自動で動き始めます。トレイのアイコンを左クリックするか「画面を開く」で画面を開き、停止するときはトレイの「終了」を押します。すでに動いているときにもう一度 exe を開くと、そのアプリの画面が開きます。

コンソールで起動する方法も使えます。`start.bat` または `codex-bridge.exe host start` で起動し、黒いウィンドウは開いたままにします。`stop.bat` または `codex-bridge.exe host stop` で止めます。この場合の画面は `http://127.0.0.1:8770/admin/` で、同じ画面の「使う」が開きます。常駐アプリの中で動いている場合、この URL は 8766 の画面へ移ります。

「使う」タブの貸す人のカードで、接続と使用量を確認してください。カードを開くと、その人への設定と、相手が決めた設定が見られます。作業中は PC をスリープさせないでください。

### 依頼のしかた（どれでも同じことができます）

**1. エージェントに頼む（おすすめ）**
Claude Code か Codex で新しい会話を始め、次のように頼むだけです。

> codex-bridge で、○○の開発を依頼して

エージェントが自分で手順を確かめ、共有フォルダを見て具体的な依頼文にし、貸す人の Codex に送り、承認待ちには内容を確かめて応え、結果を確認して報告します。
承認・権限・共有フォルダ・招待コードなど、画面の操作の多くはエージェントにも頼めます（「scripts フォルダを書けるようにして」など）。
送り先を指定したいときは、「○○さんに頼んで」のように、招待コードに付けた名前を伝えてください。

**2. 画面から直接頼む**
「使う」→「依頼」→「新しい依頼」で、内容を書き、相手・モデル・推論の強さを選んで「依頼する」を押します。既存の依頼を選んで入力欄から送ると、作業中は追加の指示、終了後は前の会話の続きになります。「中止」も依頼の詳細から行えます。

### 知らせ（承認待ちと終了）

`install-mcp.bat` は、Claude Code と Codex の知らせ用フックも入れます。エージェントを起こすのは、承認待ちと終了のときだけです。複数の依頼を並行して送れます。待つためにサブエージェントを作る必要はありません。

Codex では、追加されたフックを一度 `/hooks` で信頼してください。信頼するまでは動きません。`install-mcp.bat` を実行し直してフックが変わったときも、`/hooks` でもう一度信頼します。
Codex が知らせを待っている間は、会話は続いている扱いになります。話しかけたいときは Esc を押してください。

「使う」タブで承認を決めた場合や、フックの待ち時間が過ぎたあとの知らせは、Claude Code では、次に codex-bridge のどれかの道具を呼んだときに届きます。Codex では、次のターンの終わりに届きます。ただし、Codex には 24 時間より前の依頼の知らせは届きません。get_result か「使う」タブで確かめてください。

同じ PC の Claude Code の会話を 2 つ開いていると、タスク ID をフックが読み取れなかった依頼の知らせは、まれに別の会話に届くことがあります。

### モデルと推論の強さ

エージェントへの依頼では `send_task` の `model` と `effort`、「使う」タブでは「モデル」と「推論の強さ」で指定できます。省くと、貸す人の Codex の既定を使います。ただし、その人が許可したモデルと推論の強さの上限の範囲で選びます。
上限以下で使える推論の強さがないモデルは、候補に出ません。使えない指定は断り、使えるモデルと推論の強さを表示します。v0.2 以前の exe には指定できません。

タスク詳細には、実際に使ったモデルと推論の強さが出ます。Codex が途中で別のモデルに切り替えた場合も、そのモデルを確認できます。

### 送り先と、続きの依頼

- **相手: 自動** … 接続中で受付数と使用量に余裕のある貸す人のうち、作業件数の少ない人を選びます。同じ件数なら、使用量の余裕で選びます。5 時間枠・週間枠のそれぞれで「効いている上限 − 今の使用率」を比べ、小さいほうが大きい人を選びます。使用量がまだ届いていない人は後回し、同じ余裕なら最後に頼んだ時刻が古い人が先です。
- **名前を指定** … その貸す人に頼みます。その人が未接続・受付数の上限・使用量による停止中なら、別の人には送らず、頼めない理由を表示します。
- **続きとして依頼** … 前と同じ貸す人に送ります。会話がその人の Codex の中にあるため、別の人には引き継げません。その人が未接続・受付数の上限や、その会話が作業中なら待つか、前回の報告を添えて新しく頼んでください。使い捨てのセッションには、終わったあとの続きは頼めません。

1 人に複数の依頼を並行して頼めます。同時に受ける数は貸す人が決めます（既定 3、1〜8）。許可待ちを含め、つながっている依頼主全体で数えます。同じファイルを変える依頼は、同時に送らないようにしてください。
貸す人が複数の依頼主に Codex を貸している場合、ほかの依頼主も含めて受付数の上限に達すると自動の送り先から外れ、名前を指定しても作業中という答えを返します。空きができると再び受け付けます。ほかの依頼主の依頼文・タスク ID は見せません。protocol 4 以下、または受付数を知らせない古い exe は、従来どおり同時に 1 件までです。
「相手の許可待ち」は、貸す人が依頼を許可するのを待っている状態です。新しい依頼だけでなく、追加の指示にも事前承認が必要なことがあります。

### 共有フォルダを追加する・権限を決める

1. 「使う」→「共有フォルダ」→「フォルダを追加」でフォルダを選びます。初めは「読むだけ」です。
2. 一覧の権限を「見せない／読むだけ／書ける」から選びます。下のフォルダの規則には「親と同じ」も使えます。
3. 相対パスの起点にするフォルダで「メインにする」を押します。

変更すると反映されます。コマンドの規則などの複数行の入力は、欄からフォーカスを外すと反映されます。共有フォルダの追加と取り外し、権限の変更は作業中でもできます。フォルダを外すとメインのフォルダが共有から外れる場合や、メインを切り替える場合は、作業が終わってから行ってください。「外す」は共有の登録を外す操作で、PC のファイルは消しません。

依頼文では、メインの中を `src/app.py` のような相対パスで書けます。別の共有フォルダは `D:/tools/common-lib/helper.py` のようなフルパスで書いてください。

登録したフォルダに含まれない場所は、Codex からは見えません。中のフォルダに別の権限を付けると、より深いフォルダの設定が優先されます。ただし「見せない」は常に優先し、その中もすべて隠します。記録や合言葉を置く codex-bridge のデータフォルダを含む場所は共有できません。
コマンド実行は閉じ込めていないため、実行したプログラムは「見せない」場所や共有フォルダの外も読めます。コマンドの許可は、この点も含めて決めてください。

### 画面でできること

| 場所 | できること |
|---|---|
| 「使う」の貸す人のカード | 接続・使用量・上限・作業の状態。開くと、その人への設定と相手が決めた設定 |
| 承認待ち | コマンド実行・削除の許可／拒否。30 分返事がなければ自動で拒否 |
| 「使う」→「依頼」 | 新しい依頼、追加の指示、続きの依頼、中止、途中経過・計画・最終報告の確認、「この依頼のコマンド」の指定 |
| 「使う」→「共有フォルダ」 | 共有フォルダの追加・外す・メインの切り替えと権限 |
| 「使う」→「コマンドの規則」 | 全員共通の拒否・確認・許可リストと、作業中に書き換えたスクリプトの承認 |
| 「使う」→「招待」 | 貸す人の名前を付けて招待コードを発行 |
| 「ログ」 | アプリの動作の記録。使う側・貸す側・警告の絞り込み、検索、書き出し、フォルダを開く |
| 右上 | 全体の一時停止・再開 |

貸す人のカードを開くと、「コマンド実行」「削除の前に承認する」「相手に見せる記録」を、その人ごとに変えられます。
コマンド実行は「実行しない／許可リストだけ自動／毎回承認／すべて自動」です。新しい招待は「毎回承認」で始まります。「相手に見せる記録」では「道具の名前と対象」「道具の結果」を選び、何も選ばないと「なし」になります。

コマンドは、「実行しない」、拒否リスト、確認リスト、作業中に書き換えたスクリプトの確認（有効時）、許可リスト、モードの順で判定します。「すべて自動」でも拒否・確認が効き、書き換えたスクリプトも承認待ちにできます。許可リストは「許可リストだけ自動」で使います。拒否・確認は、つないだコマンドを個別に調べ、`cmd /c` や `powershell -Command` などの中も調べます。拒否リストは確実な防御ではなく、書き換えたスクリプトの中で同じ操作をされると防げません。

型はコマンドの先頭からトークンの順に比べます。途中にオプションが入る形も対象にするには、その位置を型に含めます。拒否・確認リストでは、たとえば `git -C ../repo push` や `git -C A:\repo push` には `git -C ** push *`、`del /q x` には `del /q *` が当たります。

「依頼」の詳細の「この依頼のコマンド」では、作業中にモードの指定と拒否・確認リストを変えられます。実際に効くモードは貸す人の設定と依頼の指定の厳しいほうです。拒否・確認は全員共通のリストに追加されます。指定を変えたあとは次のコマンドから適用されます。承認待ちのコマンドも実行直前に「実行しない」と拒否リストをもう一度調べます。

使用量の上限と超えたときの止め方は貸す人が決めます。実行モード・削除承認・記録の表示範囲は、依頼主が貸す人ごとに設定します。
貸す人は自分の PC の同じ URL の「貸す」タブで、依頼主ごとのカードから設定できます。古い版から届かない設定は「—」を表示します。詳しくは [貸す人向けの手順](friend-guide.md)を見てください。

## D. 困ったとき

| 症状 | 対処 |
|---|---|
| 貸す人が「未接続」のまま | 貸す人の PC で CB アイコンが出ているか／両方の Tailscale が Connected か／貸す人が共有の招待を受け入れたか |
| `start.bat` が「起動できませんでした」 | Tailscale が Connected か。前の `start.bat` のウィンドウが残っていないか（あれば `stop.bat`） |
| エージェントが codex-bridge を使わない | 「使う」が動いているか。`install-mcp.bat` のあとに**新しい会話**を始めたか |
| 貸す人の PC で「接続を断られました」 | 招待コードが失効・発行し直されている。新しいコードを渡す |
| 貸す人の PC でエラーの画面が出た | エラー画面に出た `crash.log` を送ってもらう。初期の場所は `%LOCALAPPDATA%\codex-bridge-agent\logs\crash.log`。保存場所を移した場合は、その場所の `logs\crash.log` |
| 続きの依頼を送れない | 前の担当者が接続中で受付数と使用量に余裕があり、その会話が作業中ではないか。使い捨て、または会話を削除した場合は、前回の報告を添えて新しく頼む |
| 変更を取り消したい | Claude Code / Codex に「さっきのタスクの変更を取り消して」と頼む（`undo_task`） |

## E. リリースを作る

`uv run python scripts/build_release.py` で ZIP を作ります。GitHub の公開リリースには `v{版}` のタグを付け、`release/codex-bridge-v{版}.zip` を 1 つ添付します。アップデート時は、この資産に GitHub が付けた SHA-256 を使います。
