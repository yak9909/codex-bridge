# codex-bridge 運用手順書（依頼主＝あなた向け）

知人の PC の Codex に、あなたの PC のフォルダで作業してもらうための手順です。
知人向けの手順は [friend-guide.md](friend-guide.md) です。配布する zip は 1 つで、依頼主も知人も同じものを使います。

v0.3.0 では、複数の知人に別々の作業を頼めます。共有するフォルダも、この PC 内の複数の場所を登録できます。

---

## A. 最初に一度だけ

事前に、この PC に Tailscale を入れてログインしておいてください（[C. Tailscale の準備](#c-tailscale-の準備)）。

### A-1. 初期設定（`codex-bridge.exe` の「使う側」、または `setup.bat`）

`codex-bridge.exe` をダブルクリックして「使う側」を選びます。exe の隣に `host.yaml` がなければ、初期設定のあと、そのまま codex-bridge が起動して管理画面が開きます（黒いウィンドウは閉じないでください）。
初期設定だけしたいときは、`setup.bat` をダブルクリックします（起動はしません）。どちらも、画面の質問に答えます（Enter だけで、おすすめの設定になります）。
共有フォルダは初期設定では聞きません。管理画面の最初にある「フォルダを選ぶ」で選ぶと、再起動なしで使えるようになり、次の起動でも設定が残ります。選ぶまでは「未設定」と表示されます。初期設定をやり直しても、選んだ共有フォルダと権限はそのままです。

| 段階 | 起きること | あなたがすること |
|---|---|---|
| 1. Tailscale の確認 | この PC の Tailscale の IP を調べる | 未接続なら、案内に従ってログイン |
| 2. 検索用の部品 | ripgrep を用意 | なし |
| 3. 設定ファイルと権限の規則 | `host.yaml` と権限の規則（`data\policy.yaml`）を作る | 必要ならメモ帳で権限の規則を開く（あとで管理画面からも変えられます） |
| 4. ファイアウォール | Windows が「変更を許可しますか？」と聞く | **「はい」を押す** |
| 5. 完了 | 次にやることを表示。Tailscale の管理画面を開くか聞く | この PC の「…」→「Share...」→ 招待リンクを知人に送る |

### A-2. `install-mcp.bat`

Claude Code と Codex（入っているほう）に codex-bridge を登録します。これで、エージェントに頼むだけで使えるようになります。
Claude Code や Codex を後から入れたときは、もう一度実行してください。

### 以前の版から更新するとき

新しい zip は、以前とは別のフォルダに展開されます。そのまま「使う側」を選ぶと、新しく初期設定が始まります（新しい招待コードが必要になり、権限の規則と共有フォルダも引き継がれません）。次の順で行ってください。

1. 古いフォルダの `stop.bat` で止める（または古い黒いウィンドウを閉じる）
2. 新しい zip を展開する
3. 古いフォルダの `host.yaml` と `data` フォルダを、新しいフォルダにコピーする
4. 新しいフォルダで「使う側」を選ぶか、`start.bat` を実行する
5. 新しいフォルダの `install-mcp.bat` を実行し直す

v0.2 からの更新でも、`install-mcp.bat` で Codex を登録し直し、知らせ用フックを入れる必要があります。Codex では `/hooks` でフックを信頼してください。フックが変わったときは、もう一度信頼します。

以前の版で作られた `friend-kit` フォルダは不要なので、消してかまいません。

### 知人に渡すもの

1. 受け取った zip と同じもの（`codex-bridge-v` で始まる zip）。知人は展開して `codex-bridge.exe` をダブルクリックし、「貸す側」を選びます。ほかのファイルは使いません
2. Tailscale の共有の招待リンク（A-1 の最後で案内する「Share...」で作ったもの）
3. 招待コード: 起動して管理画面の「招待コード」で、その知人を見分ける名前を入力 →「発行」→ その場でコピー（再表示できません）

**招待コードは、知人ごとに別の名前で 1 つずつ発行します。** 付けた名前が、依頼の「送り先」になります。同じコードを複数の人に渡さないでください。同じ名前で発行し直すと、前のコードは使えなくなります。

以前の v0.1 の exe も、v0.3.0 の依頼主側につなげられます。この版の知人側の画面や設定を使うには、exe も v0.3.0 に更新してください。更新するときは依頼主側を先に更新します。v0.2 の exe でも通常の依頼は受けられますが、モデルと推論の強さは指定できません。
メイン以外のフォルダを使うには、知人側の exe も v0.2 以降が必要です（v0.1 の exe はメインのフォルダだけで作業できます）。

※ OpenAI の規約上グレーな使い方なので、知人に伝えて了解をもらってください。

## B. 毎回

### 起動と停止

- **`start.bat`** … 起動します。黒いウィンドウが開き、管理画面がブラウザで開きます。作業中はこのウィンドウを閉じず、PC もスリープさせないでください。
- **`codex-bridge.exe`** … ダブルクリックして「使う側」を選ぶと、初回は初期設定のあと、2 回目からは exe の隣の `host.yaml` で、そのまま起動します。黒いウィンドウを閉じずに使ってください。
- **`stop.bat`** … 止めます（黒いウィンドウを閉じても止まります）。

管理画面の「Codex を貸している人」で、頼みたい知人が接続中なら準備完了です（知人が codex-bridge を起動している必要があります）。名前ごとに使用量・上限・作業中のタスク・事前承認の有無・セッションを残すかどうかが見られます。

### 依頼のしかた（どれでも同じことができます）

**1. エージェントに頼む（おすすめ）**
Claude Code か Codex で新しい会話を始め、次のように頼むだけです。

> codex-bridge で、○○の開発を依頼して

エージェントが自分で手順を確かめ、共有フォルダを見て具体的な依頼文にし、知人の Codex に送り、承認待ちには内容を確かめて応え、結果を確認して報告します。
承認・権限・共有フォルダ・招待コードなど、管理画面でできることは、すべてエージェントにも頼めます（「scripts フォルダを書けるようにして」など）。
送り先を指定したいときは、「○○さんに頼んで」のように、招待コードに付けた名前を伝えてください。

**2. 管理画面から直接頼む**
「Codex に依頼する」欄に書き、「送り先」を選んで「依頼する」。タスクを選んで「続きとして依頼する」にチェックすると、前の会話の続きになります。
作業中のタスクには、詳細の欄から追加の指示を送ったり、中止したりできます。

### 知らせ（承認待ちと終了）

`install-mcp.bat` は、Claude Code と Codex の知らせ用フックも入れます。エージェントを起こすのは、承認待ちと終了のときだけです。複数の依頼を並行して送れます。待つためにサブエージェントを作る必要はありません。

Codex では、追加されたフックを一度 `/hooks` で信頼してください。信頼するまでは動きません。`install-mcp.bat` を実行し直してフックが変わったときも、`/hooks` でもう一度信頼します。
Codex が知らせを待っている間は、会話は続いている扱いになります。話しかけたいときは Esc を押してください。

管理画面で承認を決めた場合や、フックの待ち時間が過ぎたあとの知らせは、Claude Code では、次に codex-bridge のどれかの道具を呼んだときに届きます。Codex では、次のターンの終わりに届きます。ただし、Codex には 24 時間より前の依頼の知らせは届きません。get_result か管理画面で確かめてください。

同じ PC の Claude Code の会話を 2 つ開いていると、タスク ID をフックが読み取れなかった依頼の知らせは、まれに別の会話に届くことがあります。

### モデルと推論の強さ

エージェントへの依頼では `send_task` の `model` と `effort`、管理画面では「モデル」と「推論の強さ」で指定できます。省くと、貸している人の Codex の既定を使います。ただし、その人が使わせているモデルと推論の強さの上限の範囲で選びます。
上限以下で使える推論の強さがないモデルは、候補に出ません。使えない指定は断り、使えるモデルと推論の強さを表示します。v0.2 以前の exe には指定できません。

タスク詳細には、実際に使ったモデルと推論の強さが出ます。Codex が途中で別のモデルに切り替えた場合も、そのモデルを確認できます。

### 送り先と、続きの依頼

- **自動（使用量に余裕のある人）** … 接続中で、作業中ではなく、上限で止められていない知人のうち、いちばん余裕のある人を選びます。5 時間枠・週間枠のそれぞれで「効いている上限 − 今の使用率」を比べ、小さいほうが大きい人を選びます。使用量がまだ届いていない人は後回し、同じ余裕なら最後に頼んだ時刻が古い人が先です。
- **名前を指定** … その知人に頼みます。その人が未接続・作業中・上限による停止中なら、別の人には送らず、頼めない理由を表示します。
- **続きとして依頼** … 前と同じ知人に送ります。会話がその人の Codex の中にあるため、別の人には引き継げません。その人が未接続・作業中なら待つか、前回の報告を添えて新しく頼んでください。使い捨てのセッションには、終わったあとの続きは頼めません。

作業は知人 1 人につき同時に 1 つです。複数の知人がいれば、別々の依頼を並行して進められます。同じファイルを変える依頼は、同時に送らないようにしてください。
知人が複数の依頼主に Codex を貸している場合、ほかの依頼主の作業中・承認待ちには、管理画面の「Codex を貸している人」の作業中のタスク欄に「ほかの依頼主の作業中」と表示します。そのあいだは自動の送り先から外れ、名前を指定しても作業中という答えを返します。終わると自動で待機中に戻ります。ほかの依頼主の依頼文・タスク ID は見せません。v0.1 の exe はこの通知を送らないので、従来どおりの表示です。
「使わせる側の承認待ち」は、知人が依頼を許可するのを待っている状態です。新しい依頼だけでなく、追加の指示にも事前承認が必要なことがあります。

### 共有フォルダを追加する・権限を決める

1. 管理画面の「共有フォルダと権限」で、追加したいフォルダのフルパス（絶対パス。例: `D:/tools/common-lib`）を入力するか、「参照…」で選びます。
2. 「読むだけ」か「書ける」を選び、「フォルダを追加」を押します。
3. 相対パスの起点にしたいフォルダで「メインにする」を押します。最初に管理画面で選んだフォルダがメインです。
4. ▸ で中のフォルダを開き、「上と同じ／見せない／読むだけ／書ける」を選び、「保存して反映」を押します。

追加・一覧からの削除・メインの切り替えは、その場で反映されます。作業中や承認待ちのタスクがあるときは変えられないので、終わってから操作してください。権限は作業中でも変更できます。「削除」は共有の登録を外す操作で、PC のファイルは消しません。

依頼文では、メインのフォルダの中は `src/app.py` のような相対パスで書けます。別の共有フォルダの中は `D:/tools/common-lib/helper.py` のように、ドライブ名からのフルパスで書いてください。

登録したフォルダに含まれない場所は、Codex からは見えません。中のフォルダに別の権限を付けると、より深いフォルダの設定が優先されます。ただし「見せない」は常に優先し、その中もすべて隠します。記録や合言葉を置く codex-bridge のデータフォルダを含む場所は共有できません。
コマンド実行は閉じ込めていないため、実行したプログラムは「見せない」場所や共有フォルダの外も読めます。コマンドの許可は、この点も含めて決めてください。

### 管理画面でできること

| 欄 | できること |
|---|---|
| Codex を貸している人 | 知人ごとの接続・使用量・上限・担当タスク。使えるモデルも表示し、その人だけのコマンド実行モードを選べます。こちらのしきい値と知人の上限は低いほうが効き、上限に達した人への新しい依頼を止めます。作業中は、すぐ止めて報告するよう頼むか、知人の設定で強制的に止めます |
| 貸している人の画面に見せる道具の記録 | v0.1 の貸す人の画面での表示範囲。v0.2 以降の複数接続の画面では、貸す人が接続先ごとに表示範囲を決めます。依頼文・追加の指示・Codex の発言と計画・状態・最終報告は、いつも見せます |
| 承認待ち | コマンド実行・削除の許可／拒否（エージェントも内容を確かめて応えます。30 分放置で自動拒否） |
| Codex に依頼する／タスク | 送り先を選んだ依頼、追加の指示、中止、変更の取り消し。タスク詳細の「簡易／詳細」で、途中経過・計画・道具の記録などを確認 |
| 共有フォルダと権限 | 複数の共有フォルダの追加・削除・メインの切り替え、フォルダごとの権限、コマンド実行の扱い、削除の承認 |
| 招待コード | 知人ごとの発行・失効 |
| 右上 | 全体の一時停止 |

「Codex を貸している人」の「コマンド実行」は、「全体と同じ／実行しない／許可リストだけ自動／毎回確認／すべて自動」から選びます。「全体と同じ」に戻すと、「共有フォルダと権限」の設定に従います。

知人も自分の PC の `http://127.0.0.1:8766/` で作業を確認できます。画面の「接続先」には、あなたの名前ではなく PC の住所が出ます。上限・機能の制限・事前承認・使い捨て・保存場所・作業フォルダ・記録の保管日数は、知人がその画面で決めます。詳しくは [知人向けの手順](friend-guide.md)を見てください。
作業ログの「考えの要約」は、今の Codex では空のことがよくあります。

## C. Tailscale の準備

1. https://tailscale.com/download から Windows 版を入れる
2. タスクトレイの Tailscale のアイコンを右クリック →「Log in...」→ Google などでログイン →「Connect」
3. アイコンを右クリックして「Connected」と出ていれば完了

## D. 困ったとき

| 症状 | 対処 |
|---|---|
| 管理画面が「未接続」のまま | 知人の PC で CB アイコンが出ているか／両方の Tailscale が Connected か／知人が共有の招待を受け入れたか |
| `start.bat` が「起動できませんでした」 | Tailscale が Connected か。前の `start.bat` のウィンドウが残っていないか（あれば `stop.bat`） |
| エージェントが codex-bridge を使わない | `start.bat` で起動しているか。`install-mcp.bat` のあとに**新しい会話**を始めたか |
| 知人の PC で「接続を断られました」 | 招待コードが失効・発行し直されている。新しいコードを渡す |
| 知人の PC でエラーの画面が出た | エラー画面に出た `crash.log` を送ってもらう。初期の場所は `%LOCALAPPDATA%\codex-bridge-agent\logs\crash.log`。保存場所を移した場合は、その場所の `logs\crash.log` |
| 続きの依頼を送れない | 前の担当者が接続中で、作業中・上限による停止中ではないか。使い捨て、または会話を削除した場合は、前回の報告を添えて新しく頼む |
| 変更を取り消したい | エージェントに「さっきのタスクの変更を取り消して」、または管理画面のタスク詳細の「このタスクのファイル変更を取り消す」 |
