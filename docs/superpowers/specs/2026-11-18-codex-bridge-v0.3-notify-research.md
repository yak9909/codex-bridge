# 調査: 承認待ちと終了だけをエージェントに伝える方法（2026-11-18）

要求は `2026-11-18-codex-bridge-v0.3-requirements.md` の 2 章。ここでは調べた事実だけを残す。【文書】は公式の資料・ソースに書いてあること、【推測】はそこからの推論。

## Claude Code

### A. MCP のサーバー側のタスク（MCP の版 2026-07-28 の tasks）
出典: https://code.claude.com/docs/en/mcp.md （MCP tasks that run on the server）
- 【文書】道具の呼び出しはすぐ返り、Claude Code 本体が `tasks/get` で終わりを確かめる（既定 2 秒ごと）。モデルのトークンは使わない【推測】。終わると結果がモデルに渡り、何もしていなければ自分から続きに取りかかる。`/tasks` に出る。
- 【文書】条件: Claude Code v2.1.304 以降、公開ベータ。HTTP で可。**対象はターミナルの CLI・Agent SDK・GitHub Actions だけで、VS Code 拡張とデスクトップアプリは対象外**。Bedrock など他社経由やテレメトリ無効のセッションも対象外。
- 【文書】**サブエージェントから呼ぶとタスクにならない**。`claude -p` の一発実行でもならない。
- 【文書】結果の本文は会話の記録に出ず、「MCP task … completed.」の 1 行だけ。
- 【文書】`/clear` や `/resume` の後も今の会話に届く。サーバーの再起動のときの動きは書かれていない。取り消しは `/tasks` で x（Esc では止まらない）。
- 【文書】タスクの「入力待ち」（input_required）は Claude Code が自分で答える仕組みで、モデルを起こして判断させるものではない。【推測】承認待ちはタスクを「終了」にして返し、許可の後に新しいタスクを始める形にする。
- 【文書】タスクにするかどうかはサーバーが決める。モデルが呼び出しごとに選ぶ手段はない。
- 使っているライブラリ `mcp` 2.3.0 はデータの形だけ持ち、サーバー側の処理は自分で書く。

### B. 見張りのコマンド
出典: https://code.claude.com/docs/en/tools-reference.md （Monitor / Background commands）、interactive-mode.md、headless.md、hooks.md
- 【文書】Bash の `run_in_background` は、対話モードのローカルのセッションなら時間の上限なし。終わると結果を持ってもう 1 ターン動く（headless の節と SDK の節に記載。対話モードでアイドル時に起きることは同じ仕組みと推測）。
- 【推測】タスクごとに「承認待ちか終了で抜けるコマンド」を裏で動かせば、Claude Code のバックグラウンドタスクと同じ形になる（複数可、1 つ抜けるたびに起きる、待っている間トークンなし）。代わりに、依頼のたびにエージェントがコマンドを 1 つ裏で動かす手間（1 回の道具の呼び出し）がかかり、エージェントが忘れると知らせが来ない。
- 【文書】Monitor は 1 行ごとに知らせるが、期限が最長 30 分で、切れるたびに張り直し（そのたび少しトークン）。Windows では Git Bash が要る。
- 【文書】asyncRewake のフックは、終了コード 2 で何もしていないエージェントを起こせる。プラグインの monitors はセッションの始まりで自動で動く（https://code.claude.com/docs/en/plugins/components.md#monitors）。【推測】これなら「起動するだけ」も要らない形にできる可能性があるが、未確認。

## Codex（codex-cli 0.167.0）
- 【ソース】MCP のサーバー側のタスクは**未実装**（openai/codex#48617）。`mcp_2026_07_28` の機能は版の交渉だけで、開発中・既定でオフ。長い道具の呼び出しはターンを占有する（`tool_timeout_sec` 既定 60 秒）。
- 【ソース】裏で動かしたコマンドが終わっても、モデルは起こされない（モデルが見に行く必要がある）。
- 【文書】フックの `Stop`（エージェントがターンを終えようとしたとき）で `decision: block` を返すと、その理由の文が新しい指示としてターンが続く（https://learn.chatgpt.com/docs/hooks）。既定の待ち時間の上限は 600 秒。非同期のフックでは新しいターンは始まらない（Claude Code の asyncRewake にあたるものはない）。
  - 【推測】Stop のフックが「この会話で出した依頼のどれかが承認待ちか終了になるまで」待ち、なったらその中身を返して続けさせれば、待っている間トークンなし・複数可・サブエージェント不要になる。エージェントは自分の作業を終えてから待つので、作業中に割り込まれることはない（Claude Code でも知らせはターンの合間に届くので同じ）。ただし待っている間はターンが続いている扱いで、利用者が話しかけるには Esc で止める。依頼が残っていないときはすぐ抜ける。
- 【ソース】`codex queue --thread … --message … --resume` で外から会話に文を入れられる（実験的な API `thread/queue/add`）。何もしていない会話を本当に起こすかは未確認。
- 【ソース】`wake_on_agent_messages` は開発中で、エージェント同士の連絡用。使えない。

## 試験の結果（2026-11-18、使い捨ての偽の MCP サーバーで。codex-bridge 本体は使っていない）

### Claude Code 2.1.327 — `PostToolUse` の asyncRewake フック
- 構成: 偽の `send_task` はすぐ task_id を返す。`send_task` に合わせた PostToolUse フック（`asyncRewake: true`、`timeout: 600`）が、そのタスクの終わりまで待ち、終わったら stderr に結果を書いて終了コード 2 で抜ける。
- 結果（会話を開いたままの headless、stream-json）: 2 つの依頼（20 秒・45 秒）はすぐ戻ってターンが終わった。約 20 秒後と約 45 秒後に、それぞれ**別のターンとして自動で起こされ**、正しいタスク名で答えた。それ以外で起こされることはなかった。待っている間の API 呼び出しはなし。起こされた 1 回あたり約 $0.0003（ほぼキャッシュの読み込み）。
- エージェントが別の作業（30 秒の処理）をしている間に終わった分は割り込まず、その作業のあと同じターンの中で届いた。
- `claude -p` の一発実行は、フックが終わるまで終了を待った。
- 未確認: 対話の画面（何もしていないときに起きるか）。資料では asyncRewake は何もしていない Claude を起こすとある。利用者の手で一度確かめる。
- 注意: mcp 2.x では `FastMCP` ではなく `MCPServer`。`tool_response` は配列で中身が二重に文字列化されている。フックはタスクごとに 1 つ動き続ける。

### Codex 0.167.0 — `Stop` フック
- 構成: プロジェクトの `.codex/hooks.json` に Stop フック（timeout 900）。フックは、まだ知らせていない依頼があれば、いちばん早く終わるものまで待ち、`decision: block` と結果の文を返す。なければ何もせず終わらせる。
- 結果（`codex exec`）: 依頼 2 つのあと「依頼しました」でターンが終わる → フックが待つ → 約 20 秒後に A の結果で続き → 再び待つ → B の結果で続き → 残りがないので終了。待っている間モデルの動きはなし。エージェントが別の作業（30 秒）をしている間に終わった分は、作業のあとすぐ届いた。
- 注意: 待っている間はターンが続いている扱いで、利用者は話しかけられない（Esc で止める必要。画面での見え方は未確認）。フックは利用者が `/hooks` で一度信頼する必要があり、書き換えると信頼し直し。`-c` でのフックの指定は効かず、ファイルでの指定が要る。待ち時間の既定の上限は 600 秒（900 は通った）。続けさせ続けると止まらないので、残りがないときは必ず抜ける。承認待ちでの起こし方は未試験（終了と同じ形で返せる見込み）。
