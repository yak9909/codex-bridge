## 1. 作業中の共有フォルダの変更
要望: 「作業中は共有フォルダを変えられない仕組みになっていますが、変えられるようにすることはできますか？」→「進めてよいです」（2026-11-20）。
- 追加と外すは、作業中でもできる。
- メインのフォルダの切り替えと、今のメインのフォルダを外すことは、作業中は断る（相対パスの基準が作業の途中で変わるため）。文言: 「作業中はメインのフォルダを切り替えられません。終わってから切り替えてください」「作業中はメインのフォルダを外せません（メインのフォルダが共有から外れるため）。終わってから外してください」。外すとメインが読み書きできなくなる場合（メインを含む親のフォルダだけで共有していた場合も）をこれに含め、ほかの登録でまだ共有されているなら普通に外せる。
- コマンド実行の前後の走査は、実行前に決めたフォルダの組を使う（実行中に足したフォルダのファイルを「変えたファイル」と記録しない）。
- 取り消しは、対象がもう書けない場所（共有を外した・読むだけや見せないに変えた）なら、何も変えずに全体を断る。文言: 「書き込めない場所のファイルは元に戻せません（共有を外した・読むだけや見せないに変えた）: <パス>」。
- 一時停止のあとは、一時停止の前に許可したコマンドも始めない。

## 2. 1 人で同時に複数の依頼
要望: 「一人で同時に複数を受けられるようにします」「一人一つまでは絶対にあってはならない仕様です」（2026-11-20）。
- 「1 人 1 つまで」という決まりを無くす。同時にいくつまで受けるかは、貸す人が自分の画面で決める（「同時に受ける依頼」1〜8、既定 3）。
- どの依頼の操作かは、Codex の道具の呼び出しに付く会話の ID（tools/call の _meta.threadId）で決める。決められないときは、書き込み・削除・コマンド実行を断る。
- 同じ会話で 2 つの依頼を同時に進めない（作業中の依頼の会話の続きは断る）。
- 許可待ちを複数持てる。使用量の上限を超えたら、作業中の依頼すべてを止める。
- 古い版（protocol 4 以下）の貸す人は 1 つまでとして扱う。
- 貸す人が違えば、今までも同時に依頼を進められる（「taiyo が作業中の場合、mycodex という別の Codex も使えないのですか？」への答え。待っていたのは、作業中は共有フォルダを足せなかったため。1 で直る）。

## 3. アップデート
要望: 「アップデート機能も追加したいです。起動中や作業中でもアップデートできるようにします」（2026-11-20）。
- 入手元: 依頼主も貸す人も、それぞれ GitHub の公開リリースから取る。リポジトリは利用者が公開する。
- 起動時と、そのあと 6 時間ごとに調べる。画面の「確かめる」でも調べる。取った zip は、GitHub が付ける SHA-256 で確かめる。
- 切り替え: 新しい版は先に用意し、その PC の作業中の依頼がすべて終わった時点で再起動して切り替える。
- 「依頼主の側が自動でほかの貸す人に回すのはやめてください。その人が切り替え待ちだった場合は切り替えが終わるまで待ち、タイムアウトしたら断るようにしてください」（2026-11-20）。
- 自動か確認か: PC ごとの設定で選ぶ（「自動で更新する／毎回確認する」、既定は毎回確認する）。1 つのアプリが使う側と貸す側を動かすので、設定は PC に 1 つ。
- 入れ替え: 動いている exe の名前を変えて新しい exe を置き、同じ zip のほかのファイルも入れ替えてから起動し直す。古い exe は次の起動で消す。ソースから動かしているときは更新しない。
- 版の番号が上がったリリースだけを更新として扱う。今の v0.3.0 には仕組みが無いので、最初の 1 回は手で入れ替える。

## 4. 依頼ごとのコマンドの許可
要望: 「依頼ごとに許可するコマンドを変えたりできるようにしたいです。エージェント側から指定もできるようにしたいです」（2026-11-20）。
- 依頼ごとに、コマンド実行のモードと許可リストを指定できる。ただし、貸す人ごとの設定より厳しくする方向だけ（実行しない・毎回承認にする・許可リストを絞る）。ゆるめたいときは、今までどおり貸す人ごとの設定を変える。（利用者の選択: 「厳しくするだけ」）
- エージェント（Claude Code など）は、依頼を出すとき（send_task）と作業中（別の道具）に指定できる。使うタブの依頼の詳細でも見られ、変えられる。（利用者の選択: 「依頼を出すときと作業中」）
- 実際に効くのは、貸す人ごとの設定と依頼ごとの指定の、厳しいほう。

## 5. コマンドの規則（許可・確認・拒否の 3 つのリスト）
要望: 「貸す人ごとの設定で全部承認されていたとしても、『このコマンドだけは許可しない』のようなリストを書けるようにしたい」「どのようなやり方が良いかを模索してください」。懸念: 「『リストのものだけ許可』に全部コマンドを許可すると、毎回エージェント側で依頼ごとにコマンドを指定しないといけなくなり手間が増える」（2026-11-20）。→ 下の案（Claude Code の権限の設定と同じ考え方）を利用者が選んだ。
- コマンドは、次の順に判定する。
  1. 拒否リストに当たれば断る（どのモードでも、いちばん強い）。
  2. 確認リストに当たれば、毎回承認待ちにする（「すべて自動」でも聞く）。
  3. 許可リストに当たれば、自動で実行する。
  4. どれにも当たらなければ、貸す人ごとのモード（実行しない・毎回承認・すべて自動）に従う。
- 今の「許可リストだけ自動」は「既定は毎回承認＋許可リスト」と同じ意味になる。今の設定は、意味を変えずに新しい形へ移す。
- モードは今の 4 つ（実行しない・毎回承認・許可リストだけ自動・すべて自動）を意味を変えずに残す。「毎回承認」は許可リストに当たっても承認待ちにする（許可リストが効くのは「許可リストだけ自動」だけ）。拒否・確認のリストはどのモードでも効く。（利用者の選択 2026-11-21: 「厳しいモードを残す」。3 つにまとめると、今「毎回承認」の人の許可リストのコマンドが黙って自動になるため）
- 3 つのリストは全員共通で、使うタブの「許可リスト」タブを「コマンドの規則」にして並べる。モードは貸す人ごと（今までどおり）。
- 依頼ごとの指定（4 節）は、拒否・確認のリストを足すことと、モードを厳しくすることだけ。依頼ごとに許可リストは足せない。
- 当たるかどうかは、&&・|・; でつないだコマンドの一つ一つと、cmd /c・powershell -Command・bash -c などの中まで調べる。それでも、Codex が書いたスクリプトの中で同じことをされると防げない。拒否リストは確実な防御ではないことを、画面と文書に一言書く。
- 「作業中に書き換えたスクリプトは承認待ちにする」は、「すべて自動」のときにも効かせられるようにする。
- 画面の形は、確認用の環境で撮った画像を見ながら決める（0 節）。
